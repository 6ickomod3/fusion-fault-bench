Deterministic estimator-output evaluation

Find the point where fusion stops helping.

When does camera–LiDAR fusion become worse than trusting the modality declared healthy in a controlled single-sensor fault?

Fusion Fault Bench isolates that question with paired counterfactual sequences, explicit reported covariance, controlled fault injection, complete-sequence inference, and strict content-addressed evidence. It evaluates matched known-object BEV centers—not a detector, planner, or safety system.

  • CPU only
  • Known object IDs
  • Paired randomness
  • Versioned contracts
  • Aggregate-only public replay

System architecture

A narrow question, made auditable end to end.

Every run begins with immutable scientific intent and ends with validated evidence. Runtime provenance is recorded separately, so local paths and timestamps never alter the experiment identity.

Analytic Gaussian

Known expected loss and population crossover references.

Seeded procedural

Constant-velocity temporal scenes with controlled support.

nuScenes-mini metadata

Recorded latent geometry, pose, calibration, and timing; no raw payload reads.

  1. Freeze intent

    Validate the manifest, profile, seeds, severity grid, methods, and estimands.

  2. Form outputs

    Generate camera and LiDAR estimates with separate actual error and covariance.

  3. Inject faults

    Apply bias, uncertainty, calibration, timing, or availability changes.

  4. Compare methods

    Evaluate unimodal estimates, fixed fusion, health fallback, and diagnostics.

  5. Publish evidence

    Aggregate by sequence, bootstrap, validate, hash, and publish without overwrite.

Claim boundary

Precise evidence is useful evidence.

The benchmark is intentionally narrow. It is designed to make one fusion-layer question interpretable, not to stand in for an autonomous-driving safety case.

What the benchmark can support

  • Controlled estimator-output comparisons under explicit proxy faults.
  • Signed fusion-versus-healthy loss and preregistered crossover analysis.
  • Causal observable health-policy behavior and clean/fault tradeoffs.
  • Reproducibility claims bound to frozen intent, code, and aggregate artifacts.
  • M5 design-level grounding in recorded geometry, pose, calibration, and timing.

What it does not claim

  • Raw camera or point-cloud realism, detector quality, or learned perception.
  • Naturally occurring fault rates or real sensor-noise distributions.
  • Unknown-object association, set prediction, or false-detection performance.
  • Planning, collision, closed-loop policy, certification, or production safety.
  • That a local profile check is M5 execution evidence or an M5 result.
